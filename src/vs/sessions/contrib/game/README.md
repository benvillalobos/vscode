# Worklands playtest

Game is a spatial control surface for real Agents Window sessions, not a simulated progress dashboard.

1. **Choose Workspace** in the command dock and select an available provider.
2. **Default Model** and **Default Permission** in the command dock set what brand-new recruits are dispatched with. **Default Model** lists the target provider's models once at least one session with it exists; **Default Permission** is always available and applies the provider's own default when left at **Default**.
3. **New Task** creates a movable task site with a name and instructions. Select the task and click its title or description in the detail pane to edit it in place. **Save** keeps the change locally; **Cancel** discards it. Descriptions support multiple lines. Editing never dispatches work; the next dispatch includes the updated brief.
4. **Spawn Blob** creates a free local recruit. Its inspector status is **Draft - No Session** until dispatched. Click the selected blob's name in the detail pane to rename it, or double-click its name on the map. Double-click a task site to minimize it, hiding its assigned blobs and their tethers; double-click again to expand.
5. Drag the recruit into a task's highlighted zone, or select it and use **Assign Task**. The large ring matches the assignment radius (44 map units), scaling with the map; overlapping zones choose the nearest task. Dropping outside all task zones unassigns it. Moving a task carries its assigned crew; moving a parent carries its local child formation.
6. Review **Task Brief Sent with Orders**, add instructions, then **Dispatch**. A new recruit creates a real session in the selected workspace, without creating a worktree, using the command dock's default model and permission level. An existing unit sends to its own chat, unaffected by those defaults. The map remains open. The full task brief is sent once per task assignment and again after the task is edited; otherwise later orders to the same chat send only your new instructions, since the chat already has that context.
7. **Bring Session** places an existing session on the map. **Spawn Child** prepares an additional chat when that provider supports it. Provider-created visible chats and child sessions appear as linked satellites; hidden chats stay hidden and read-only workers cannot be dispatched.
8. Double-click a blob's body or use **Open Chat** to open its conversation in a resizable right-hand chat pane without leaving the game. Child blobs open their own chat. **Close Chat** returns focus to the selected map piece. Draft blobs have no chat until dispatched; double-clicking a blob's name still renames it.
9. Blobs use the existing chat pet artwork to convey status, with only their name underneath. Dispatching pets type; working pets have the chat pet's speech bubble. At most three working or dispatching pets animate, prioritizing the selected pet. Blocked or failed pets look worried. A finished turn gives one completion flourish and the pet sleeps automatically, without an acknowledgment step. Sleeping pets keep their name, position, and task tether, if assigned. Dispatch wakes them immediately. Drafts and unavailable sessions never appear asleep. Status remains available in the inspector and to screen readers; task labels count resting pets even when their crew is hidden.
10. Right-click a blob for **Archive Session** and **Delete**. **Archive Session** (previously **Mark as Done**) archives its real session and removes it from the map; it is unavailable for individual child chats. **Delete** uses the existing confirmation to delete the real session or child chat; an undispatched draft is only removed locally. **Remove from Map** remains a separate, map-only action.
11. Drag the background to draw a selection rectangle, then release to select all visible blobs whose centers fall inside it. Dragging works in any direction, including while zoomed or scrolled; task sites and minimized crews are excluded. Shift-drag adds to the selection, and Escape cancels without changing it. Mission control shows a portrait for every selected blob; hover for its name, or click to select only that blob and restore its individual orders. **Delete Blobs** in Command acts on the selected blobs, reusing session/chat deletion confirmations and removing drafts locally. Selecting a session and its child chats does not delete the same conversation twice.
12. With multiple blobs selected, **Mark Blobs as Done** in Command uses the session list's done action to archive their real sessions and remove their blobs from the map. Conversations are not deleted and can be restored from the session list. Select a child chat's parent blob too; selecting only child chats never marks an unselected parent session done. Each session is marked once, even when several selected blobs represent it. Undispatched drafts are removed locally. Missing sessions or in-flight dispatches disable the action.

Solid gold lines mean task assignment. Dotted purple lines mean parent/child relationships. Labels, changed-file counts, and activity come from live provider state. A sleeping blob means its turn completed, not that the task was verified or finished.

When a blob's reported context window usage is **above 50%**, its normal face or sleeping pose becomes fretful, with a small **!** cue. Working speech bubbles and the actual session status are preserved. Hover or select the blob to see its context percentage; screen readers and Accessible View expose the same information. It returns to its normal pose at 50% or below, including after compaction. Each child chat uses its own usage, not its parent's. The percentage uses the latest available usage report and the model's configured context window, as in chat's context meter. No usage is guessed or persisted: chats without a loaded model or reported usage keep their normal pose until data becomes available.

The map has twice the viewport's width and height at 100% zoom. Scroll or use the scrollbars to explore; **Ctrl+scroll** (or **Shift+scroll**) zooms in and out around the pointer, from 50% (the whole map) to 200%. Hold the **middle mouse button and drag** to pan the camera, including when starting over a blob or task, without moving pieces. Release the button or press Escape to stop panning. The command dock stays fixed. Task artwork has four times its previous area. Dragging a blob over a task pushes the blob outward to keep both pieces visible; the adjusted drop position is saved without dispatching work.

## Safety and persistence

Spawning, moving, assigning, opening, and reloading never dispatch work. Dispatching a brand-new recruit uses the command dock's default model and permission level, falling back to the selected provider's own defaults when neither is set; no permission elevation beyond that chosen default is applied. Busy and approval-blocked units must be handled in their normal chat. Errors preserve unsent orders for explicit retry.

The workspace-local board stores task briefs, unsent orders, positions, session/chat URI links, minimized tasks, and the default model and permission level. Pet poses follow live provider status, including after reload. It does not sync or execute on restoration. **Remove from Map** does not delete sessions or cancel requests; **Delete** explicitly deletes the linked session or chat after confirmation. Missing sessions remain unavailable rather than silently becoming new sessions.

## Keyboard and accessibility

With the map background focused, **+** and **-** zoom, **0** resets zoom to 100%, and arrow keys pan. Arrow keys on a focused piece still move that piece.

**Shift-click**, **Shift+Enter**, or **Shift+Space** toggles a blob in the selection. Tab reaches the selected-blob portraits; Left/Right arrows, Home, and End navigate them. Enter or Space on a portrait selects just that blob. Group selection never dispatches orders; select an individual portrait to edit or send that blob's orders.

With multiple blobs selected, hover or focus a portrait to reveal its top-right **Remove from Selection** close button. Clicking it deselects only that blob; it never removes the blob from the map, archives its session, or deletes anything. Keyboard users can Tab from the portrait to the close button and press Enter or Space. Focus moves to the next portrait (or the previous one when removing the last portrait).

For a selected task, Tab to its title or description and press Enter or Space to edit. Enter saves a title or description; Shift+Enter inserts a new line in a description. Ctrl+Enter and Cmd+Enter also continue to save. Escape cancels and returns focus to the edited field. Selecting another piece discards an unsaved edit.

Tab reaches map pieces and dock commands; Enter selects a piece. Tab to the selected blob's name in the detail pane and press Enter or Space to rename it; Enter confirms the new name and Escape cancels. Arrow keys move a focused piece. **Assign Task** replaces dragging. Shift+F10 or the context-menu key opens the focused blob's menu. Escape closes the menu and restores focus, or cancels a drag. Accessibility Help describes the controls, and Accessible View lists tasks, assignments, parent links, and live status. Each blob's accessible label includes its status even though no status text appears beneath it. Reduced motion and high-contrast themes are supported.

The first playtest intentionally omits combat, pathfinding, resource economies, and automatic delegation. Pets stay in place: no wandering, automatic sorting, or chat-pet physics. It reuses the existing Stable/Insiders chat pet assets, with quiet static resting poses and a static working pose for reduced motion.
